01 Simulation · Gazebo Harmonic

BEVNav: camera-only indoor navigation

A ROS 2 navigation stack for a skid-steer rover with one pan-mounted RGB camera and no range sensor. Each camera image becomes a bird's-eye-view occupancy grid that the rover plans and drives on, and keeps as a map of the space it has explored.

  • Six 60° pan scans fused into a 360° occupancy grid and a persistent 50 × 50 m log-odds map. Floor masks come from the simulator or a SegFormer-B0 model fine-tuned on simulated data.
  • Cost map, greedy planner, 20 Hz pure-pursuit controller and route-based sub-goals to back out of dead ends, with EKF localization (robot_localization) and REP 105 frames.
  • Evaluation harness over 6 warehouse scenarios: seeded trials recorded as MCAP bags, automated metrics and figures, plus unit and launch tests.

02 Real robot · BeetleBot

Active perception for a mobile robot

Scores how good the camera's view of a target is and moves the rover to fix the weakest factor, asking a vision-language model only once the view passes cheap local checks.

  1. Snapshot
  2. YOLOv8 + metrics
  3. Weakest factor
  4. Corrective move
  5. Re-score
  • Four local metrics on the target's box (sharpness, exposure, framing, YOLOv8 confidence), each scaled so 0.5 is the pass threshold and they can be compared.
  • Each failure maps to a move: retake, orbit 30°, rotate, approach or back off 0.15 m. After a fixed number of attempts the robot retraces to the best view it found.
  • Gemini judges occlusion and framing only after local checks pass, which cuts API calls. The snapshot pipeline and orbit motion run on the physical BeetleBot.

03 Real robot · BeetleBot

Autonomous spatio-temporal memory assistant

A ROS 2 robot that patrols a lab, describes what it sees with a vision-language model, remembers every observation with its place and time, and answers questions such as “What changed in the last 30 minutes?”

  1. Navigate
  2. Capture
  3. VLM scene parse
  4. Memory
  5. Change detection
  • Teach-and-repeat navigation: drive the route once by keyboard and the robot replays it, with no map or Nav2 required.
  • Compares each zone with its last visit and logs typed events (object added, moved or removed, walkway blocked, door opened); YOLOv8n cross-checks the person count.
  • Four laptop-side ROS 2 nodes run beside the robot's unchanged vendor stack. The robot moves only while armed, stops for obstacles within 0.39 m and drives only to recorded zones.
  • Web dashboard with live status, zone cards, an event feed with photos and an end-of-day closing check.
